## Summary

CVE-2026-110264 is an unauthenticated vulnerability in GitLab's Org-mode rendering path. The org-ruby renderer takes the first word of a TODO directive line and interpolates it raw into a regular expression; a keyword containing more than 32,767 bounded repeats overflows Onigmo's 16-bit repeat ID, producing an out-of-bounds read in the match-cache walk and an out-of-bounds write at match time. A public GitLab project containing a crafted .org file can be rendered by an unauthenticated visitor; heap grooming through the request body is the intended path to code execution as the git user. The included PoC validates the bug end-to-end and provides an unauthenticated render oracle (multi-second render, a server-side Timeout error, Workhorse 502, Puma BUG output); the full heap-groomed code-execution chain remains per-build weaponization research, matching the upstream status as of 2026-10-31.

## Vulnerability Details

### Root Cause

In `org-ruby` 0.9.12, `headline.rb#parse_keywords` re-compiles a regex from the raw keyword:

```ruby
@headline_text.sub!(Regexp.new("^#{@keyword}\\s*"), "")
```

The parser escapes the keyword once when validating the `#+TODO:` line, but this second interpolation uses the raw string (CWE-94). A keyword with more than 32,767 bounded repeats passes Onigmo's signed 16-bit repeat-ID field, wrapping it negative. The negative ID is then used in the match-cache count walk (OOB read) and at match time (OOB write). GitLab renders Org-mode content for public projects through `Banzai`/`org-ruby`, so an unauthenticated visitor can reach the engine.

### Attack Vector

An attacker commits a crafted `.org` file to a **public** GitLab project (or uses the blob preview endpoint with a `file_path` ending in `.org`). The file contains a `#+TODO:` line with a keyword built from more than 32,767 `[[:word:]]*` repeats and a headline that forces the match. A request to the rich-viewer sink (`GET /:namespace/:project/-/blob/:ref/:path.org?format=json&viewer=rich`) renders the file in the GitLab Rails/Puma worker. The request body can be used for heap grooming; the PoC's loud, stealth, single-directive and burst variants exercise the same sink.

### Impact

On a successfully weaponized build: unauthenticated RCE as the `git` OS user, with access to repositories, CI variables, runner tokens, `gitlab-secrets.json`, and the GitLab database — i.e., full instance compromise. The included PoC demonstrates the crash/oracle stage (render timeout, 502/hang, `[BUG]` in Puma stderr) and local root-cause reproduction; it does **not** ship a full shell. The sister CVE-2026-97229 (same GitLab/Onigmo regex family) is in CISA KEV and was weaponized by Rapid7, which is why this class is treated as critical even before a public full chain.

## Proof of Concept

### Step-by-Step Reproduction

1. **Generate the payload** — `python3 poc.py payload --repeats 35000 -o p0.org` (loud) or `--stealth` / `--single`.
2. **Commit it to a public project** — upload `p0.org` to the `main` branch of a public GitLab project (the full lab provisions this).
3. **Render it unauthenticated** — request the rich-viewer sink for the `.org` blob (`?format=json&viewer=rich`), or use the preview endpoint without committing.
4. **Observe the oracle** — a vulnerable instance shows a multi-second render, `Timeout::Error`/`OtherMarkup` on the server, a Workhorse 502/hang, and `[BUG]` in `puma_stderr.log`. The PoC's `--verify` sends a benign control and compares deltas; `--burst` mimics the detection threshold.

## Detection & Indicators of Compromise

- GitLab Rails `exceptions_json.log`: `Timeout::Error` with `extra.class_name: OtherMarkup` and `extra.file_name: *.org`.
- Workhorse/Puma: `502`/`badgateway: EOF` bursts on `.org` blob routes; Puma stderr `[BUG]` stack touching `org-ruby`, `headline.rb`, `regexp_helper.rb`, `match_at`, `onig_search_gpos`, `onig_compile`, `compile_tree`, `rb_str_sub_bang`.
- Render latency: `.org` renders taking 10–19 s while benign files render in ~0.1 s.
- Burst pattern: repeated `.org` requests from one client (the upstream detection rule uses ≥5 / 30 minutes).
- Public projects with `.org` files containing very long `#+TODO:` / `#+SEQ_TODO:` / `#+TYP_TODO:` keywords.

**SIEM / IDS rule (example):**

```text
alert http any any -> any any (msg:"GitLab .org render oracle burst"; \
  content:".org"; http_uri; content:"viewer=rich"; http_uri; sid:9002612;)
```

## Remediation

| Action | Detail |
|---|---|
| **Patch** | Upgrade GitLab CE/EE to 18.11.13, 19.0.10, 19.1.9, 19.2.9, 19.3.6, 19.4.3 or 19.5.1 (or later). The fix includes the Ruby/Onigmo repeat-ID patch and `gitlab-markup` 2.2.0. |
| **Workaround** | Disable Org-mode rendering or restrict it to trusted projects/users; block or rate-limit `.org` rich-viewer requests; do not rely on WAF version rules alone. |
| **Config Hardening** | Keep public-project creation restricted, monitor render timeouts and 502 bursts, and patch Ruby 3.3.13 / 3.4.12 / 4.0.9 (or vendor equivalents) where the engine is bundled. |
