## Summary

QEMUtiny is a memory corruption exploit chain in QEMU CXL Type-3 emulation that combines an out-of-bounds read (`GET_LOG`) with an out-of-bounds write (`SET_FEATURE`). The PoC leaks QEMU process pointers and then corrupts CXL device-adjacent state to steer execution toward attacker-controlled callbacks. In the demonstrated setup, this enables code execution in the host QEMU process from a guest context.

---

## Vulnerability Details

### Root Cause

The chain relies on two mailbox handler bugs in `hw/cxl/cxl-mailbox-utils.c`:

1. `cmd_logs_get_log()` treats a byte-based mailbox offset as an array index when computing the source address for `memmove()`, enabling out-of-bounds reads.
2. `cmd_features_set_feature()` accepts attacker-controlled offsets for feature write-attribute structures and fails to enforce `offset + length <= sizeof(struct)`, enabling out-of-bounds writes into neighboring fields.

### Attack Vector

An attacker with execution inside the guest uses MMIO mailbox access to the emulated CXL device BAR, first issuing crafted `GET_LOG` requests to leak pointers and derive QEMU/libc addresses, then issuing crafted `SET_FEATURE` payloads to overflow CXL Type-3 structures. A subsequent sanitize/media operation traverses corrupted state and triggers a forged callback chain.

### Impact

Potential guest-to-host escape in vulnerable QEMU configurations, with attacker-controlled execution flow inside the QEMU host process. This can lead to full host compromise depending on host hardening and runtime constraints.

|---|---|

| **Workaround** | Disable or avoid exposing vulnerable CXL Type-3 functionality in untrusted guest scenarios |
